!!Heading!! Welcome to Day R Modding Tool (version 0.0.4)!

This program automates mod creation for Day R Survival (version 1.694 and below). It handles unpacking the game archive, decompiling scripts, compiling modified files, packing the mod, checking code for errors via Luacheck, working with bytecode via assembler/disassembler, and decoding UTF-8 — all without requiring extra tools.

Program settings are saved in the user folder:
C:\Users\<Username>\DayR_MB\
This allows you to keep your chosen font, profiles, and interface configuration even when moving the EXE file.

!!Heading!! Installation and Launch
1. Download DayR_Modding_Tool.exe
2. Place it anywhere convenient (Desktop or a separate folder)
3. Run it by double-clicking

Antivirus may ask for an exception on first run — the program is safe, all embedded utilities are legal.

On first launch, the program:
- Creates DayR_MB folder in user profile (C:\Users\<Username>\DayR_MB\).
- Copies configuration files and example plugin there.
- When you select a project folder, creates tools folder inside it and copies all utilities.

!!Heading!! Interface Overview
- Top panel: language selection (Russian/English), Profiles (📁), Settings (⚙️), Help (?) buttons — all with icons and tooltips.
- Project panel: folder path and "Open mod_scripts folder" button.
- Main buttons (five rows, configurable via config.json):
  - Row 1: Unpack, decompile all, mass compile (warning), pack mod.
  - Row 2: Clean project, file manager, compile one .lua, decompile one .lu.
  - Row 3: Select resource.car, check one .lua, reset mod_scripts, clear modded_lu.
  - Row 4: Lua console, check all .lua, command console.
  - Row 5: Decode UTF-8, disassemble .lu → .asm, assemble .asm → .lu.
- Log window: displays messages and errors.
- Bottom panel: status, "Save logs", and "Clear log" buttons.

!!Heading!! Step‑by‑Step Workflow
1. Choose a project folder (empty or existing).
2. Copy resource.car from the game (assets folder) into the resources folder inside your project, or click "Select resource.car" to pick the file.
3. Click "Unpack resource.car" – all files are extracted into original_scripts.
4. Click "Decompile all .lu → .lua" – you get readable code in mod_scripts. On repeat decompilation, a choice dialog appears.
5. Edit the needed .lua files (use the built-in editor or external editor) inside mod_scripts.
6. Check your code – click "Check one .lua" or "Check all .lua". Luacheck will show errors in the log. Fix them before compilation.
7. Open "File Manager", find your edited file, and click "Build" – it compiles to .lu and goes into modded_lu. Repeat for all changed files.
8. Click "Pack resource.car (mod)" – choose where to save the new resource.car.
9. Copy the resulting file into the game folder (backup the original) and launch the game.

!!Frame!!
Important: Never use the "Compile all .lua → .lu" button – it recompiles everything and almost always breaks the game! This button is red and requires confirmation.
!!EndFrame!!

!!Heading!! Profile Management
Profiles allow you to save project settings and quickly switch between different mods.

How it works:
- A profile stores name, description, project folder path, creation and modification date.
- Profiles are stored in %USERPROFILE%\DayR_MB\profiles.json.
- You can create, edit, select, or delete a profile.

How to use:
1. Click the "Profiles" button (📁) in the top panel.
2. In the window that opens:
   - "Create Profile" — enter a name and specify the project folder.
   - "Select Profile" — the program will automatically switch the project folder.
   - "Edit" — change the path or description.
   - "Delete" — the profile will be removed (the project folder remains).

!!Heading!! Code Checking with Luacheck
Luacheck is a static analyzer that finds potential errors in Lua scripts without running them.

What it checks:
- Unused variables
- Undeclared global variables
- Accessing uninitialized variables
- Unreachable code
- Variable shadowing

How to use:
- Click "Check one .lua" and select a file – results appear in the log.
- Click "Check all .lua" – all files in mod_scripts are checked.
- In File Manager, each file has a "Check" button for quick verification.

It is recommended to check your code before each compilation – this prevents game crashes.

!!Heading!! Built‑in Editor
- In File Manager, the "Open" button launches the built-in editor.
- Syntax highlighting (if pygments is installed).
- Buttons: "Save", "Save and compile", "Close".
- "Save and compile" – saves and compiles the file to modded_lu.

!!Heading!! Lua Console and Command Console

Lua Console (for executing code):
- Open via the "Lua console" button in row 4.
- Enter code, click "Run" or press Ctrl+Enter.
- Result appears in the output field.
- Convenient for testing small scripts.

Command Console (for managing the program):
- Open via the "Command Console" button in row 4.
- Available commands: help (list commands), clear/cls (clear output), exit/quit (close), lua (open Lua console), and plugin commands.
- Use ↑ and ↓ arrows for quick access to command history.

!!Heading!! Assembler and Disassembler (Bytecode Work)
Tools for working with Lua bytecode (disassembling .lu to .asm and assembling back).

How to use:
1. Disassemble .lu → .asm:
   - Click "Disassemble .lu → .asm" in row 5.
   - Select a .lu file (e.g., from original_scripts).
   - The program will create a .asm file with assembler code.

2. Assemble .asm → .lu:
   - Click "Assemble .asm → .lu" in row 5.
   - Select a .asm file.
   - The program will build a .lu file that can be used in the game.

Important: These functions use Python scripts from utils/asm/ and do not require external .exe files.

!!Heading!! UTF-8 Decoding
Many Day R scripts contain text as numeric escape sequences (e.g., \208\184\208\179\209\128\208\176 instead of "игра").

How to use:
1. Click "Decode UTF-8" in row 5.
2. Select a folder with .lua files (e.g., mod_scripts).
3. The program will recursively process all .lua files, converting them to UTF-8 without BOM.
4. The result will appear in the log (how many files processed, how many errors).

!!Heading!! Font Settings
1. Click the Settings button (⚙️) in the top panel.
2. Select one of the available fonts: Classic, RO.ttf (Red October), freemono.ttf, russo_one.ttf.
3. If the font is missing, the program will offer to open the folder to add the .ttf file.
4. Click "Save" and restart the program.

!!Heading!! Frequently Asked Questions
❓ Why is _temp_extract empty but files appear in the project root?
This is a corona-archiver.py quirk – the program automatically moves files to original_scripts. Ignore it.

❓ Game won't start after installing the mod?
Make sure you didn't use the forbidden button. Check that you compiled only changed files and they ended up in modded_lu with the correct structure. Try "Reset mod_scripts" and recompile. Also check your code with Luacheck – there might be a syntax error.

❓ How to restore original files after editing?
Use "Reset mod_scripts" – it will delete modified .lua and recreate them from originals.

❓ How to add my own font?
Place your .ttf file in the font folder (next to the EXE or in resources) and select it in settings.

❓ Can I use the tool with other game versions?
The tool has been tested on versions 1.683 and 1.694. For versions newer than 1.694, the file structure may differ – use at your own risk.

❓ What is Luacheck and why is it needed?
Luacheck is a tool for finding code errors without running it. It helps you catch issues before they cause game crashes. It is strongly recommended to check your code before compilation.

❓ Where are program settings stored?
All settings (font, profiles, interface configuration) are stored in C:\Users\<Username>\DayR_MB\. This allows you to keep settings when moving the EXE file.

❓ What is the command console?
The command console allows you to control the program via text commands (help, clear, lua). Useful for advanced users who prefer working with the keyboard.

❓ How to add my own plugin?
Place a Python script with the register(plugin_manager) function in C:\Users\<Username>\DayR_MB\plugins\. The program will automatically load the plugin on startup. An example plugin (example_plugin.py) is created automatically on first launch.
